## 问题的形状

我执业中有一半时间在做一件事：打开 PDF，读合同条款，切到浏览器查法条，切到北大法宝查案例，再切回来写审查意见。三四个窗口来回跳，一小时能审一份算快的。

痛点不是"不会审"，是"工具太碎"。

## 偶然的发现

GitHub 上看到一个项目：[claude-for-legal-ZH](https://github.com/CSlawyer1985/claude-for-legal-ZH)，浙江海泰的陈石律师做的，把 Anthropic 官方的 claude-for-legal 整套中国法本地化了。12 个领域插件，从商事合同到知识产权到劳动用工，每个都有专门的审查技能。

我的第一反应不是"这能替代律师"，而是——如果审查意见的框架让 agent 跑，我只做判断和决策，是不是就能把那三四个窗口关掉两个？

## 装三个，不是十二个

12 个插件里我只装了最相关的三个：

| 插件 | 用途 | 配置深度 |
|---|---|---|
| commercial-legal | 商事合同审查（买卖、SaaS、保密协议） | 快速模式 |
| ip-legal | 商标/专利/著作权/商业秘密 | **完整配置** |
| employment-legal | 劳动用工（录用、解除、规章制度） | 快速模式 |

每个插件安装后要跑一次冷启动面试（cold-start interview），回答一系列关于你执业场景的问题——管辖地在哪里、客户类型是什么、审查立场偏向哪一方、deal-breaker 是什么。插件把这些写成一份实务画像（CLAUDE.md），之后每次审查都读它。

这个设计很聪明。不是通用的"帮你审合同"，而是"按**你的**标准审合同"。

## 两个法律数据库，两种命运

插件体系里有两个法律数据库 MCP：元典（Yuandian）和北大法宝（PKULaw）。

### 元典：原生 MCP，37 个工具直接用

元典用的是 stdio 传输协议，npx 启动，Claude Code 原生支持。装完就能用，37 个工具覆盖法律法规检索、案例语义搜索、企业工商信息查询、涉诉文书列表。

实际用起来像这样——

```
我：查一下竞业限制补偿标准的相关法条

Claude：[调用 yuandian_law_vector_search]
返回最高人民法院司法解释、劳动合同法相关条文、
人社部竞业限制合规指引……
```

不需要我去北大法宝的网站，不需要选数据库，不需要想关键词用什么组合。一句话，语义搜索直接出结果。

### 北大法宝：streamableHttp 的坑

北大法宝配置也写进了 `.mcp.json`，但它用的是 `streamableHttp` 协议——Claude Code 的插件系统**不加载这个类型**。服务器是活的（curl 手动调完全正常），但工具列表里就是看不到。

变通方案：写两个 shell 脚本封装 curl 调用。

```bash
# 精确查法条
pkulaw-get "中华人民共和国民法典" "第一百四十三条"

# 语义搜索
pkulaw-search "竞业限制补偿标准"
```

放在 `~/.claude/bin/`，Claude 通过 Bash 工具调用。不优雅，但能用。

**使用策略：** 默认用元典（调用次数无限制），北大法宝只在做精确法条交叉验证时用（调用次数有限）。

## 一天的工作流

### 上午：审一份 SaaS 订阅协议

把 PDF 往终端一扔，说"审一下这份 SaaS 协议"。

插件自动识别协议类型，路由到 `/commercial-legal:saas-msa-review`，按我的审查指引逐条检查——自动续约条款、价格调整机制、数据可迁移性、SLA、再处理者权利。每个风险点标注红/黄/绿，附法条依据和修订建议。

同时后台调用元典 MCP 查相关法条，引用标注来源：`[元典检索]` 或 `[北大法宝]`。

输出是一份审查备忘录，格式是 `SaaS订阅协议 审查备忘录 — 2026-05-25`。

### 下午：商标确权 + 劳动纠纷

客户问某个商标能不能注册。`/ip-legal:clearance` 跑排除性筛查，元典查近似商标案例，输出标注清单（不是法律意见，是筛查结果）。

另一个客户被前员工告了，要分析解除是否合规。`/employment-legal:termination-review` 按管辖地（广州）的特定规则审查，自动标记高风险因素——三期女职工、工伤职工、工龄 10 年以上。元典查地方法院审判指引，北大法宝验证关键条文原文。

## 不是替代，是压缩上下文切换

这套工具做的事情，本质上是一个上下文管理器：

- **合同条款** → 插件按审查指引逐条扫描
- **法条依据** → 元典/北大法宝直接查，不用开浏览器
- **案例参考** → 语义搜索替代关键词组合
- **审查意见** → 框架由 agent 生成，律师做判断和决策

我还是要读条款，还是要判断风险等级，还是要做最终决策。但三四个窗口变成了一个终端。

## 给同行的建议

如果你也是律师，想试试这套工具：

1. **先跑冷启动面试**，不要跳过。审查指引写得越具体，输出质量越高
2. **元典 MCP 是核心**，确认 API key 配好了再装插件（`/plugin install` 会覆盖手动配置）
3. **北大法宝的 streamableHttp 暂时不能原生用**，等 Claude Code 更新或用脚本变通
4. **所有输出都是审查草稿**，不是法律意见——最终责任还在律师
5. 从一个领域开始试，不要一次装 12 个

工具不替代专业判断，但能让你把花在切窗口上的时间，省回来看案子本身。
